# مسارات API

كل الاستجابات JSON تحت `/api`. جلسة الدخول محفوظة في cookie باسم `mazad.sid`. المسارات المحمية تتحقق من نشاط الحساب وصلاحياته في قاعدة البيانات. الأخطاء تعيد `message` وحالة HTTP مناسبة.

الدخول موحد: `POST /api/login` يقبل الهاتف أو البريد وكلمة المرور دون اختيار نوع الحساب، ويعيد الدور الفعلي. حقل `role` القديم اختياري للتوافق ولا يمنح أي صلاحية. يعيد `/api/me` قيمة `is_primary_admin`؛ يوجد حساب رئيسي واحد في `platform_settings.primary_admin_id`. مسارات قائمة الحسابات وتعديل حالتها وصلاحياتها محصورة به. الحسابات ذات دور `admin` الأخرى مساعدون إداريون فقط.

## إعادة بيع سيارة مسجلة

رقم الهيكل فريد في `vehicles`، أما `cars` فهي إعلانات مستقلة مرتبطة بهوية المركبة عبر `vehicle_id`. يبقى الإعلان المباع وصوره ومستنداته وفواتيره دون نقل إلى حساب المالك الجديد. عند تأكيد الاستلام فقط، تُحدَّث الملكية الحالية ويُضاف حدث ثابت في `vehicle_ownership_history` داخل معاملة إتمام البيع نفسها.

- `GET /api/account/vehicles`: مركبات الحساب الحالية ذات مبيعات مكتملة، مع `has_live_listing`.
- `GET /api/account/vehicles/:id/resale`: بيانات الهوية الأساسية للمالك الحالي لبدء إعلان جديد؛ لا يعيد مستندات أو صور المالك السابق.
- `POST /api/cars`: يقبل رقم هيكل مسجل بعد اكتمال البيع السابق، بصور وأوراق جديدة. يمنع طلبًا أو إعلانًا قائمًا آخر للهوية نفسها ويرفض اختلاف الماركة والموديل والسنة بعد البيع.
- اعتماد كل إعلان جديد له رسوم عرض مستقلة وفق السياسة الحالية؛ تعديل الإعلان نفسه لا يكرر الرسوم.
- إذا اختلف العارض عن المالك المسجل، يحتاج الاعتماد إلى `ownership_transfer_confirmed: true` و`expected_owner_id` المطابق للمالك الحالي، إضافة إلى فحص المستندات ونسختها. هذا المسار للمراجعة الإدارية لانتقال الملكية خارج المنصة؛ تقديم الطلب وحده لا يغيّر الملكية.
- `GET /api/admin/cars/:id/history`: سجل ملكية المركبة والمبيعات السابقة للإدارة فقط، مع أسماء الأطراف وأرقام الفواتير وروابط المزادات.
- لا يمكن تعديل إعلان مباع، ولا تغيير رقم هيكل إعلان له مزاد سابق. يظل منع المزادين المفتوحين قائمًا، ويضاف إليه منع إعلانين قائمين للمركبة نفسها.

يطبّق التحديث `014_vehicle_identity_resale.sql` ترحيل البيانات القائمة دون حذفها. يُشغَّل عبر `npm.cmd run migrate`؛ يمكن إعادة تطبيقه دون إعادة نقل الملكية أو تكرار السجل.

## تعديل العرض المرفوض وإخفاء المباع

تظهر في «سياراتي» ملاحظات الإدارة وزر «تعديل العرض وإعادة إرساله» للطلب المرفوض. يفتح نموذج البيانات والصور والمستندات المحفوظة مع سبب الرفض، ويحفظ التعديل عبر `PATCH /api/account/cars/:id` ثم يعيد الطلب إلى `pending_review` بنسخة مستندات جديدة دون إنشاء إعلان آخر. يظل التعديل لصاحب الإعلان المسموح له بالعرض ودون مزاد مفتوح فقط.

عندما تصبح السيارة `sold` بعد إغلاق المزاد مع فائز، تختفي من القائمة العامة ومن صفحات السيارة والمزاد والعروض وأوراق الملكية للزوار والحسابات غير المرتبطة بالبيع. تعيد الروابط المباشرة 404. يبقى الأرشيف متاحًا للبائع والمشتري المرتبط بفاتورة غير ملغاة والإدارة، بعد فحص نشاط الحساب وإصدار جلسته من قاعدة البيانات. لا تحذف الصور أو الفواتير أو سجل الملكية. تُحدّث القائمة والتفاصيل كل 15 ثانية وعند عودة التركيز، ولوحة المزاد كل 5 ثوانٍ.

حالة `ended` تعني انتهاء وقت قبول المزايدات وانتظار إغلاق المدير، بينما `closed` تعني أن الإغلاق وتحديد النتيجة اكتمل. السعر والوقت والصلاحيات تُراجع في الخلفية وقاعدة البيانات، حتى لو أرسل المستخدم طلبًا خارج الواجهة.

الحساب الموحد يستخدم دور user ويملك عرض السيارات والمزايدة معًا. صلاحيات admin تُفحص من أدوار الحساب في قاعدة البيانات، ولا توجد جلسة منفصلة لكل وظيفة. login يقبل role=user افتراضيًا أو admin للدخول الإداري. القيمتان buyer وseller القديمتان تُفسّران كـ user للتوافق فقط.

## الجوازات والصلاحيات ورسوم العرض

- `passport_image`: صورة واحدة JPG/PNG/WebP حتى 5MB، إلزامية لإنشاء حساب جديد. تُفحص وتُعالج وتُحفظ مع الحساب في معاملة واحدة. الحسابات السابقة تبقى صالحة دون جواز بأثر رجعي.
- `GET /api/admin/users/:id/passport`: مدير نشط فقط، صورة خاصة مع `private, no-store`. لا يوجد رابط عام أو تنزيل للمستخدم العادي.
- `GET /api/me`: يتضمن `can_list,can_bid,has_passport,is_primary_admin` دون مسار الملف.
- `PATCH /api/admin/users/:id/permissions`: المدير الرئيسي فقط، القيم المنطقية `can_list,can_bid,admin`. منح `admin` يعني المساعدة الإدارية ولا يمنح صلاحية تفويض آخرين. ينهي جلسات المستهدف عند التغيير ويسجل القرار في سجل ثابت. يمنع تعديل صلاحيات المدير الرئيسي؛ تُراجع صلاحية المنفذ وهوية المدير الرئيسي مجددًا داخل المعاملة.
- `GET /api/listing-policy`: عام، يعيد `listing_fee,currency,charged_at=first_approval`؛ رسوم التشغيل 10 د.ل.
- الاعتماد الأول يخصم الرسوم من رصيد العارض المتاح، مع قفل السيارة والمحفظة وتسجيل حركة `listing_fee` مرتبطة بـ`car_id`. يعيد 409 عند نقص الرصيد دون اعتماد أو خصم. لا تتكرر الرسوم عند التعديل وإعادة الاعتماد. السيارات المعتمدة سابقًا معفاة من الخصم بأثر رجعي.
- المحفظة تعرض حركة الرسوم ومرجع السيارة؛ ملخص الإدارة يعرض `listing_fee_total`. لم تتغير عمولة فواتير الفوز البالغة صفرًا.

التفاصيل في [سياسة الحساب والعرض](account-policy.md).

## المحفظة التجريبية

| الطريقة | المسار                       | البيانات                                                              |
| ------- | ---------------------------- | --------------------------------------------------------------------- |
| GET     | /api/account/wallet          | الرصيد والمتاح والمحجوز والحجوزات وآخر 100 حركة؛ summary=1 للملخص فقط |
| POST    | /api/account/wallet/top-up   | amount وrequest_key UUID، شحن وهمي بحد مليون دينار للعملية            |
| POST    | /api/invoices/:id/pay-wallet | سداد فاتورة شراء مملوكة للمستخدم؛ تكراره لا يكرر الخصم                |

جميع هذه المسارات تتطلب دور user. تعاد demo=true وcurrency=LYD في بيانات المحفظة. amounts سلاسل عشرية بثلاث خانات. payment_mode=demo_wallet افتراضي للمزادات الجديدة، وmanual يحتفظ بالسداد اليدوي.

بيانات المزاد العامة تتضمن server_time وsoft_close_seconds وpayment_mode وhas_reserve وreserve_met وmy_held_amount، دون كشف قيمة reserve_price. راجع docs/auction-rules.md.

## الملكية ودورة التسليم

`DELETE /api/admin/cars/:id` متاح للمدير لحذف أي سيارة في جميع الحالات، بما فيها السيارات القديمة ذات سنة تصنيع غير صالحة. يُخفى العرض من الموقع وقوائم صاحبه والإدارة، وتُلغى مزاداته المجدولة والنشطة ويُفك حجز المزايدة عليها داخل معاملة واحدة. تبقى المزايدات السابقة والفواتير والضمان وسجلات الدفع والملكية والرسوم محفوظة؛ حذف العرض لا يلغي الفواتير ولا يرد السداد أو رسوم العرض تلقائيًا. يستمر طرفا البيع في تسوية الفواتير القائمة، ولا يعيد انتهاء المهلة أو إلغاء المعاملة عرض السيارة المحذوفة. تُحفظ هوية المدير وتوقيت الحذف وتُرسل إشعارات لصاحب العرض والمزايدين. تكرار الحذف يعيد النجاح دون تكرار الأثر، والسيارة غير الموجودة تعيد 404.

رفع سيارة جديدة يتطلب multipart مع `images` (1–10) و`ownership_documents` اختياريًا (حتى 5 صور)، صور JPG/PNG/WebP بحد 5MB للصورة. تحديث الطلب يبقي مستنداته الحالية إذا لم تُرسل مجموعة جديدة، ويستبدل المجموعة كاملة إذا أُرسلت. يعاد طلب المراجعة ويزداد `ownership_revision` عند كل تعديل. تظهر أوراق الملكية للعامة عبر مسارات المزاد فقط عندما يعتمد المدير الملكية؛ بعد البيع تقتصر على طرفي البيع والإدارة. لا تعاد مسارات التخزين الداخلية أو صور الجواز.

- `GET /api/auctions/:id/ownership`: قائمة صور أوراق الملكية للزوار والمزايدين مع روابط العرض. يرجع قائمة فارغة إذا اعتمد المدير الملكية دون مرفقات، و404 إذا لم يوجد مزاد متاح بملكية معتمدة.
- `GET /api/auctions/:id/ownership/:documentId`: محتوى الصورة بعد التحقق من انتمائها لسيارة المزاد وحالة الاعتماد، مع `Cache-Control: no-store`. لا يسمح باستخدام معرف مستند سيارة أخرى.
- يظل الوصول المباشر إلى `/uploads/private` ممنوعًا. مسارات الإدارة التالية تبقى محمية حتى بعد إتاحة نسخة العرض عبر المزاد.

| الطريقة | المسار                           | البيانات والصلاحية                                                                                                                       |
| ------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| GET     | `/api/admin/cars/:id/ownership`  | إدارة فقط؛ روابط المستندات المحمية                                                                                                       |

الفواتير تعيد `due_at,sale_status,settlement_state,handover_at,completed_at,closed_at,dispute_reason`. السداد التجريبي ينقل الرصيد إلى الضمان، لا إلى البائع مباشرة. `escrowed_payments` و`pending_proceeds` في ملخص المحفظة منفصلان عن الرصيد المتاح. الدفع بعد المهلة يعيد 409 ويثبت الإلغاء وفك الحجز؛ العامل الدوري ينفذ الإجراء أيضًا بعد إعادة تشغيل الخدمة. الدفع وتأكيد الاستلام المتكرران آمنان من تكرار الخصم والصرف؛ إعادة الإلغاء المطبق تعيد 409 ولا تكرر الاسترداد.

إشعارات الحساب عبر `GET /api/notifications`، وإشعارات الإدارة عبر `GET /api/admin/notifications` للمدير فقط. لكل قائمة عداد `unread` مستقل؛ `POST` إلى `/:id/read` أو `/read` ضمن مسار القائمة يغيّر حالة القراءة في القائمة نفسها فقط. لا يقبل مسار الحساب اختيار النوع الإداري عبر معاملات الطلب.
